## What is built

`stalk/research/execution_log.py` is an independent read-only observer. Agent starts it alongside the existing panic, brief and review loops, polling every five seconds; `stop_background()` cancels and awaits all four tasks. It has no order, arming, settings-write, runner-decision or trade-store interface. The frozen runners and their standard trade reasons remain unchanged.

Weekday IST slots: **09:15:30, 09:20, 09:25, 11:15, 11:20, 15:05, 15:10**. A request must begin within 60 seconds of its slot; a response at or after the deadline is retained as late. Exchange timestamps must be the same IST day and within 60 seconds before receipt, allowing at most five seconds of future clock skew. Missing/stale times do not establish a current quote. Every missed slot gets an explicit missed envelope, without a later price substituted for it. Weekdays/quotes do not constitute an official holiday calendar.

Each `data/execution/YYYY-MM-DD.jsonl` line is one complete snapshot envelope with one `rows` entry per requested symbol. It records schedule/request/receipt/exchange times, symbol/provenance, LTP, bid/ask and sizes, all returned valid depth levels, total buy/sell quantity, source-provided lower/upper circuit bands, public MIS membership and derived evidence. An atomic file replacement commits a whole slot; recorded slots survive restarts unchanged. Corrupt evidence raises visibly instead of being silently replaced. This assumes the existing single Agent process; concurrent recorder processes are not supported.

Candidates are the day's already observed brief top eight plus both runners' already observed top eight and every pick, deduplicated by symbol. Provenance includes each source's observation time. The runners decide from completed bars **after 09:25**. Final picks can therefore be absent from an earlier brief/snapshot; the review reports these as missing. Later picks are matched only to their actually recorded 09:20 symbols, never to later quotes. No runner timing or selection change was made.

## MIS and circuit evidence

Quotes use the existing logged-in KiteMCP client's **`get_quotes` only**. Logged-out, failed, omitted and malformed quotes remain unavailable. No automatic login or broker acceptance probe occurs. Timestamp-only responses do not count as quotes. LTP-only or one-sided responses can lack spread evidence; `spread_known_count` makes this visible.

Zerodha publishes allowed intraday stocks in its [public equity margin calculator](https://zerodha.com/margin-calculator/Equity/); its [MIS-block support page](https://support.zerodha.com/category/trading-and-markets/margins/margin-leverage-and-product-and-order-types/articles/what-does-the-error-rms-blocked-for-sm-nse-cm-mis-broker-zerodha-block-type-all-mean) directs users to that list. Source HTML was checked through the agent-reach web-reader route and a bounded direct read during implementation. Production parses explicit `data-scrip` / positive `data-mis_margin` table attributes, not a guessed list.

Fetch once per IST date, cache success **or failure** in `data/execution/mis/YYYY-MM-DD.json`, save successful raw HTML beside it. Nonempty validated membership: listed=true, unlisted=false. Fetch/schema/empty failure: all statuses null. Yesterday's success cannot become today's membership. The source's own publication may be older than retrieval: the raw page preserves that limitation. Public-list membership is **not actual broker acceptance**, a side-specific permission guarantee, or an assurance that intraday restrictions will not change later that day. No test order was sent.

Bands come only from quote fields `lower_circuit_limit` / `upper_circuit_limit` (or explicit circuit aliases). Absent bands stay null. Distance is measured from LTP in bps. At-band compares source price and band with tiny numeric tolerance. A lower-band lock needs explicitly empty bid depth; an upper-band lock needs explicitly empty ask depth. Missing relevant depth/bands makes lock status unknown. No lock is inferred from candles.

## Displayed-depth estimates

Spread = `(ask - bid) / midpoint * 10000`. For a ₹5,000 hypothetical whole-share order, quantity is `floor(5000 / best opposing price)`. Buy walks asks ascending; sell walks bids descending. Save intended/visible-filled/unfilled quantities, complete-fill VWAP, adverse midpoint-to-VWAP slippage and additional impact beyond the best opposing price. This is a fixed-quantity depth walk; the resulting notional can differ slightly from ₹5,000 as levels worsen.

Insufficient/missing depth or zero affordable shares has **null full-order VWAP/slippage/impact**. One-sided depth can still supply a VWAP/impact with null midpoint slippage. Crossed books cannot supply cost estimates. Displayed size may disappear before a real order; there are no realised fills, fees or return estimates here. Quote freshness is necessary evidence, not an execution guarantee.

## API and daily review

`GET /api/execution` returns `{execution: null}` before a file exists, otherwise the latest day with `snapshots`. Each includes status/reason/times, requested `symbols_seen`, quote share, known-spread median/count, known-MIS share/count/coverage, known-circuit count, a tri-state any-locked/at-band flag, flagged symbols, notes, H19 status and detailed rows. MIS share uses **known statuses**, with coverage shown beside it. Quote share uses all requested symbols. Empty/missed denominators and missing medians stay null; a missed snapshot's symbol count is null. An unresolved circuit status cannot become an all-clear.

The 15:35 review adds `execution_evidence` with separate strict/loose final picks matched against the 09:20 snapshot: per-pick spread, buy fill estimate, MIS/lock status; median spread and hypothetical slippage; spread-plus-impact median; missing quote, incomplete-depth, locked, non-MIS and unknown-status pick lists. Descriptive medians omit unknowns **only with missing lists exposed**; they cannot satisfy a decision gate with missing costs. Existing review/journal idempotence remains intact. UI work is assigned to Claude in `HANDOFF.md`.
