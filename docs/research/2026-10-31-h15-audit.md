## Repair and timing

`stalk/sim/price_basis.py` resolves same-day cached official OPEN/PREVCLOSE (shared bhav cache, then H9), reading only those two fields into the decision path. It rejects either available Yahoo component if its relative difference exceeds 1%, and rejects invalid present official data rather than falling back. Missing Yahoo predecessor bars do not prevent use of an available official reference. Official symbol/day absence permits explicitly marked `yahoo_fallback` only.

The small source-attributed `data/price_basis_actions.json` is generated from cached explicit split/bonus Record Date notices. A record date is conservatively treated as an ex-date proxy only if its publication precedes that session's 09:15; future notices never reject earlier decisions. Unknown/malformed notices do not become invented dates. This inventory is incomplete and is not an adjustment-factor service. Already-announced action dates are skipped even if two unadjusted sources agree. Every rejected stock-day logs **“price data mismatch”**, with its component/action reason. No retrospective rescaling, winning-symbol exclusions or rule thresholds changed.

Auction OPEN and the prior reference are signal-time facts; the end-of-day bhavcopy is used as their historical record. Same-day CLOSE/HIGH/LOW/value never determine this guard. Exact 09:15 data vintages and later exchange corrections cannot be independently reconstructed. The existing first-bar lock test, full execution-path requirement and completed-candle stop timing remain intact. Frozen `panic.py` is untouched.

The replay/script now pass the index threshold explicitly. The old weeks script mutated `panic.INDEX_GAP`, but Python had already bound `market_qualifies`' default to −0.5%; that approach could not correctly rerun the loose variant. Explicit threshold reconstruction matches all previously saved strict/loose results, and fixed-path reruns use −0.5%/−0.3% without mutating the frozen module.

`save_to_history` deletes only the exact simulation account's prior sessions/trades before replacement, preventing removed picks from lingering under the same ids. No paper-journal sessions are deleted.

## Live runner

Live stock gaps already use NSE pre-open metadata **previousClose** and **iep**; there was no Yahoo previous-close denominator to replace. NSE documents the pre-open close as adjusted on action ex-dates ([NSE pre-open market notes](https://www.nseindia.com/market-data/pre-open-market-cm-and-emerge-market)) and describes auction OPEN/reference handling ([auction specification](https://www.nseindia.com/static/products-services/equity-market-pre-open)). That pre-open reference must not be conflated with raw bhavcopy PREVCLOSE.

A cheap guard now compares Yahoo's first-bar open with NSE's auction open (>1% relative disagreement rejects/logs the candidate). Both implied gaps use the same NSE denominator, so an unadjusted Yahoo prior close cannot create a false rejection. Missing `iep` no longer substitutes `lastPrice`, which at the 09:25 fetch could be a normal-session trade. Its historical `PanicPaper.replay` helper also uses the shared official-price resolver/provenance. Neither live version's thresholds changed; no runner was launched.

## H7c / H7d: affected despite official daily prices

H7c and H7d compute equity gaps as same-day official OPEN/PREVCLOSE. Their intraday open-to-close return units are coherent within each day; they do not suffer Yahoo's half-price versus official-price mixing. **Their selection/ranking can nevertheless be wrong because the denominator can remain the raw cum-action close.** They can also displace genuine gaps in the top-two portfolio and contaminate random-selector/grid comparisons. Removing only identified trades would not reconstruct the counterfactual portfolio.

Both original 429-row panic selection sets contain **11** matches to cached explicitly dated split/bonus notices; the 409-trade non-ETF account also contains all 11.
